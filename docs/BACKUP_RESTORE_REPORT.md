# BACKUP_RESTORE_REPORT.md — Отчёт о резервном копировании VetCare

## 1. Тип базы данных

**SQLite** — файловая база данных `vetcare.db`

## 2. Стратегия backup

### Что копируется:
- `vetcare.db` — база данных (все таблицы: user, client, pet, appointment)
- `app/static/uploads/` — загруженные файлы (если есть)
- `.env.production` — конфигурация (без реальных секретов в backup)

### Где хранится:
- Локально: папка `backups/` в корне проекта
- Рекомендуется: облачное хранилище (Google Drive, Яндекс.Диск)

## 3. Команды backup

### Автоматический backup (scripts/backup.bat):
```bash
scripts\backup.bat
```

**Что делает:**
1. Создаёт папку `backups/` если её нет
2. Копирует `vetcare.db` с временной меткой
3. Выводит путь к созданному backup

**Пример вывода:**
```
Backup создан: backups\vetcare_20260610_143022.db
Размер: 2.4 MB
```

### Ручной backup:
```bash
copy vetcare.db backups\vetcare_manual.db
```

## 4. Команды restore

### Автоматический restore (scripts/restore.bat):
```bash
scripts\restore.bat backups\vetcare_20260610_143022.db
```

**Что делает:**
1. Останавливает Docker-контейнер
2. Копирует backup в `vetcare.db`
3. Запускает контейнер
4. Проверяет доступность приложения

## 5. Тестирование backup/restore

### Сценарий тестирования:

**Шаг 1: Создание тестовых данных**
- Создать клиента: "Тестовый Клиент"
- Добавить питомца: "Тестовый Кот"
- Создать запись на приём

**Шаг 2: Создание backup**
```bash
scripts\backup.bat
```
Backup создан: `backups\vetcare_20260610_143022.db`

**Шаг 3: Удаление исходной БД**
```bash
del vetcare.db
```
 Приложение не запускается (ожидаемо)

**Шаг 4: Восстановление из backup**
```bash
scripts\restore.bat backups\vetcare_20260610_143022.db
```
 БД восстановлена

**Шаг 5: Проверка данных**
- Открыть http://127.0.0.1:5000
- Войти: admin / admin123
- Проверить наличие "Тестовый Клиент" и "Тестовый Кот"

 Данные восстановлены полностью

## 7. Рекомендации

1. **Автоматизация:** Настроить cron-задачу для ежедневного backup
2. **Хранение:** Копировать backup в облако (не только локально)
3. **Ротация:** Удалять backup старше 30 дней
4. **Мониторинг:** Проверять размер backup (резкий рост = проблема)
5. **Тестирование:** Раз в месяц проводить полный restore-тест
