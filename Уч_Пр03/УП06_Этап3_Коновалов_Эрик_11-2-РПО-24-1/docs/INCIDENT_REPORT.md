# INCIDENT_REPORT.md

## 1. Инцидент

**BUG-02: Стандартная 404-страница Werkzeug вместо кастомной**

При переходе на несуществующий URL (например, `/nonexistent_page`) пользователь видит техническую страницу Werkzeug с traceback, что ухудшает UX и может раскрыть внутреннюю структуру приложения.

## 2. Где обнаружено

Локально и в Docker-контейнере (development и production режимы).

## 3. Как воспроизвести

1. Запустить приложение: `python -m app.run`
2. Открыть браузер на `http://127.0.0.1:5000`
3. Ввести в адресную строку: `http://127.0.0.1:5000/this_page_does_not_exist_xyz`
4. **Фактический результат:** Страница Werkzeug "Not Found" с техническим текстом
5. **Ожидаемый результат:** Красивая страница с сообщением "Страница не найдена" и кнопкой возврата

## 4. Диагностика

**Проверенные файлы:**
- `app/routes.py` — нет обработчика 404
- `app/__init__.py` — нет регистрации errorhandler
- `app/templates/` — нет шаблона 404.html

**Логи:**
```
127.0.0.1 - - [10/Jun/2026 15:30:22] "GET /nonexistent_page HTTP/1.1" 404 -
```

**Причина:** Flask по умолчанию использует встроенную страницу Werkzeug для 404-ошибок, если не зарегистрирован кастомный errorhandler.

## 5. Причина

В приложении не был зарегистрирован обработчик ошибок 404 через `@app.errorhandler(404)`.

## 6. Исправление

**Изменённые файлы:**

1. **`app/routes.py`** — добавлен обработчик:
   ```python
   @app.errorhandler(404)
   def page_not_found(e):
       return render_template('404.html'), 404
   ```

2. **`app/templates/404.html`** — создан новый шаблон с:
   - Заголовком "Страница не найдена"
   - Описанием проблемы
   - Кнопкой "Вернуться на главную"
   - Единым стилем с остальными страницами

## 7. Проверка

**Выполненные команды:**
- `scripts\test.bat` — все 17 тестов пройдены 
- `ruff check app/` — линтер без критических ошибок 
- `black --check app/` — форматирование корректно 
- GitHub Actions CI —  Passed
- Ручная проверка: переход на `/nonexistent` показывает кастомную страницу 

## 8. Итог

 **Проблема полностью исправлена.**

Пользователь теперь видит понятную страницу вместо технической ошибки. Улучшение соответствует принципам хорошего UX и безопасности (не раскрывает внутреннюю структуру приложения).
