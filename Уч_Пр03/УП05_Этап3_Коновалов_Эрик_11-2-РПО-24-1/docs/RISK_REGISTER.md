# RISK_REGISTER.md — Безопасность и эксплуатация VetCare v2.1.0

## Матрица рисков безопасности и эксплуатации

| ID | Риск | Причина | Вероятность | Влияние | Уровень | Мера снижения |
|----|------|---------|-------------|---------|---------|---------------|
| **SEC-01** | **Утечка .env в Git** | Случайный коммит с реальными паролями | Средняя |  Высокое | 🔴 Критический | .gitignore, pre-commit hook, GitHub secret scanning |
| **SEC-02** | **Доступ к чужим данным** | Нет проверки владельца записи (doctor может видеть записи другого doctor) | Высокая | 🔴 Высокое | 🔴 Критический | Добавить проверку `appointment.doctor_id == current_user.id` |
| **SEC-03** | **Уязвимая зависимость** | Устаревшая библиотека с известными CVE | Средняя | 🟡 Среднее | 🟡 Средний | Регулярный `pip-audit`, Dependabot |
| **SEC-04** | **Потеря данных БД** | Сбой диска, случайное удаление | Низкая | 🔴 Высокое | 🟡 Средний | Автоматический backup.bat + хранение в облаке |
| **SEC-05** | **Brute-force на форму входа** | Нет rate limiting | Высокая | 🟡 Среднее | 🟡 Средний | Flask-Limiter, CAPTCHA после 3 попыток |
| **SEC-06** | **Отсутствие HTTPS** | Трафик в открытом виде | Высокая | 🔴 Высокое | 🔴 Критический | Nginx + Let's Encrypt для production |
| **SEC-07** | **XSS-атаки** | Недостаточная санитизация ввода | Низкая | 🟡 Среднее | 🟢 Низкий | Jinja2 автоматически экранирует, но проверить пользовательский HTML |
| **SEC-08** | **Session hijacking** | Перехват cookie | Низкая | 🟡 Среднее | 🟢 Низкий | SESSION_COOKIE_SECURE=True, HTTPONLY |
| **OPS-01** | **Сервис не поднимается после сбоя** | Нет проверки restart/logs | Средняя | 🟡 Среднее | 🟡 Средний | restart: unless-stopped, check_deploy.bat |
| **OPS-02** | **Открыт лишний порт** | Неверная настройка Docker | Низкая | 🟡 Среднее |  Низкий | Проверка ports-check.bat, firewall |
| **OPS-03** | **Нет мониторинга** | Неизвестно о падениях | Средняя |  Среднее | 🟡 Средний | Sentry, healthcheck с алертами |
| **OPS-04** | **Нет автоматического backup** | Ручной backup забывается | Средняя |  Высокое | 🟡 Средний | Cron-задача для backup.bat |

## Приоритеты снижения рисков

### 🔴 Критические (устранить до production):
1. **SEC-02** — Добавить проверку владельца данных
2. **SEC-06** — Настроить HTTPS
3. **SEC-01** — Настроить pre-commit hook

### 🟡 Средние (устранить в ближайшем будущем):
4. **SEC-05** — Интегрировать Flask-Limiter
5. **OPS-04** — Настроить автоматический backup
6. **OPS-03** — Интегрировать Sentry

### 🟢 Низкие (можно отложить):
7. **SEC-07** — Проверить пользовательский HTML
8. **OPS-02** — Проверить firewall

## Вывод

Проект имеет **3 критических риска** (SEC-01, SEC-02, SEC-06), которые необходимо устранить перед промышленной эксплуатацией. Для demo-стенда текущий уровень рисков приемлем при условии документирования и плана mitigation.
